Detailed Description

Realtime struct for the AudioPath.RootOutput path (Unity 6+).

Implements RootOutputInstance.IRealtime, writing Csound output directly into Unity's main audio output — bypassing the AudioMixer entirely. No AudioSource is required; audio is mixed additively into the final hardware output.

Processing is split across three stages per mix frame:

  • EarlyProcessing — no-op; see remarks on EarlyProcessing for why the spin buffer is not filled here.
  • Process — no-op; PerformKsmps cannot run inside a Burst job because it is a P/Invoke call.
  • EndProcessing — fills Csound's spin buffer (NativeAudioInput, audio input routes) immediately before each PerformKsmps call, runs the PerformKsmps loop, and copies the spout into the ChannelBuffer that Unity mixes to hardware.

The struct is unmanaged and stored in Unity's audio memory, so _ksmpsIndex and _startupFadeIndex persist correctly across consecutive callbacks — exactly as in CsoundRealtime on the IAudioGenerator path.

JobHandle Csound.Unity.CsoundRootRealtime.EarlyProcessing ( in RealtimeContext context,
ProcessorInstance.Pipe pipe )
inline

Stage 1: intentionally empty.

_ksmpsIndex always resets to 0 right after a PerformKsmps call, so the first real ksmps boundary in a fresh buffer lands at f == ksmps, never at f == 0. Calling the spin-fill callback here with a hardcoded offset of 0 does not correspond to where EndProcessing actually performs, and would fire a second time when the real boundary is reached — double-invoking OnSpinFillCallback per buffer. Since that callback drives CsoundUnityNativeAudioInput.FillSpinBuffer, which does a consuming read from the native ring buffer, the duplicate call drains one extra ksmps block of input per DSP buffer, starving the ring buffer over time (audible as input drop-outs when combining NativeAudioInput with RootOutput). The spin-fill is done once, at the correct offset, inside EndProcessing — exactly as CsoundRealtime does on the IAudioGenerator path, which has no EarlyProcessing equivalent at all.

void Csound.Unity.CsoundRootRealtime.EndProcessing ( in RealtimeContext context,
ProcessorInstance.Pipe pipe,
ChannelBuffer output )
inline

Stage 3: run the PerformKsmps loop and copy spout samples into output . Content written here is additively mixed into Unity's main audio output: no AudioMixer, and the AudioSource is not read.

output belongs to this instance alone — Unity's docs call it the buffer you "return the main result of your computation to the system in", sized from the format this instance was given in Configure, and the system is what renders every RootOutputInstance into the final mix. So plain assignment is right and output.Clear() on an early return silences only this instance, never a sibling. Worth stating because the additive mixing invites the opposite reading, under which both would be bugs.

The corollary is a real one for users: this path bypasses the AudioMixer, so nothing attenuates it before the sum. Several loud RootOutput instances at once will clip where the same material through an AudioSource would not.
