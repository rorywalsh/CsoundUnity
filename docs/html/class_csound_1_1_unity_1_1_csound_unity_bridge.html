Detailed Description

The managed wrapper around one native Csound instance: it creates Csound, compiles the csd, and exposes the calls CsoundUnity needs — channels, score events, the spin and spout buffers, function tables and teardown. One bridge belongs to one CsoundUnity.

◆ Destroy()

virtual bool Csound.Unity.CsoundUnityBridge.Destroy ( )
inlinevirtual

Frees the native Csound instance and its message buffer. Idempotent.

Safe to call from any thread but the audio one, at any time: before anything is freed, CloseToAudioThread shuts the bridge to new audio-thread callers and waits for the ones already inside. That wait is capped — see its doc for what crossing the cap means. A call from the audio thread itself is refused below, with an error. A subclass that drives Csound from a thread of its own has to join it before calling this — see CsoundWorker.

The handle and the cached pointers are cleared before anything is freed, so that a caller that got in anyway hits the == IntPtr.Zero checks in the hot path rather than reading released memory. Keep both: the handshake stops new callers, the nulls cover the one already inside.

Returns
true when the instance is gone — freed here, or already freed by an earlier call. false when called from an audio callback or an array-channel operation did not finish within the teardown wait. Keep the bridge reference and retry from the main thread: the native instance is retained rather than freed beneath an active caller.

Reimplemented in Csound.Unity.CsoundWorker.

◆ PerformKsmps()

int Csound.Unity.CsoundUnityBridge.PerformKsmps ( )
inline

Advances Csound by one ksmps block, filling the spout buffer, and caches the spout/spin pointers on the first successful call.

Returns

Zero while the performance is ongoing, a positive value when the score has ended, or DestroyedSentinel when this bridge has already been freed. Test for score end with > 0, never != 0 — the latter reads a freed instance as a finished score, which latches performanceFinished and, with domain reload disabled, carries into the next Play session.

> 0 loses nothing: csound.h documents csoundPerformKsmps as returning "false during performance, and true when performance is finished" and defines no negative error return, so there is no error code for this to swallow. CsoundWorker exits its loop on any nonzero value, including the destroyed-instance sentinel.

◆ Reset()

virtual bool Csound.Unity.CsoundUnityBridge.Reset ( )
inlinevirtual

Returns the Csound instance to its pre-compilation state, keeping it alive and reusable: the orchestra and control channels are gone afterwards. Compile again before performing, and set the channel values again. Keeps the host sample rate, ksmps, audio IO and message buffer.

Audio callbacks are suspended during reset and remain silent while waiting for a new orchestra. Call CompileOrc to compile it, then Start to start performance explicitly. Compilation alone does not resume audio. Expect a gap in audio. A subclass that drives Csound from a thread of its own has to stop that thread first: the audio-thread handshake does not see it, the way Destroy joins before freeing.

Returns
True when reset succeeded; false if the instance is unavailable, the call comes from its audio callback, or the callback could not be suspended within 200 ms. A refused reset preserves engine state, but waiting for a callback can silence audio for up to 200 ms. Unavailable on WebGL.

Reimplemented in Csound.Unity.CsoundWorker.

◆ TryEnterAudio()

bool Csound.Unity.CsoundUnityBridge.TryEnterAudio ( )
inlinepackage

Claims this bridge for the duration of one audio callback. Returns false when the instance is being destroyed, reset or awaiting start, and the caller must produce silence without touching the bridge at all.

Every audio-thread entry point pairs this with ExitAudio in a finally: CsoundUnity.OnAudioFilterRead, CsoundRealtime.Process and CsoundRootRealtime.EndProcessing. It is claimed once per DSP block, not per sample, so the cost is volatile flag reads and two interlocked operations per block.

The flag is checked twice on purpose. The first check is the cheap common case. The second closes the window where the destroy set _closing between that check and the increment: without it the destroy could see a count of zero, start freeing, and only then have this caller appear.
