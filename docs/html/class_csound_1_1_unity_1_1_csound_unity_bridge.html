◆ Destroy()

virtual bool Csound.Unity.CsoundUnityBridge.Destroy ( )
inlinevirtual

Frees the native Csound instance and its message buffer. Idempotent.

Safe to call from any thread but the audio one, at any time: before anything is freed, CloseToAudioThread shuts the bridge to new audio-thread callers and waits for the ones already inside. That wait is capped — see its doc for what crossing the cap means. A call from the audio thread itself is refused below, with an error. A subclass that drives Csound from a thread of its own has to join it before calling this — see CsoundWorker.

The handle and the cached pointers are cleared before anything is freed, so that a caller that got in anyway hits the == IntPtr.Zero checks in the hot path rather than reading released memory. Keep both: the handshake stops new callers, the nulls cover the one already inside.

Returns
true when the instance is gone — freed here, or already freed by an earlier call. false only when the destroy was refused because it came from inside an audio callback on this same instance. A caller that owns the reference must keep it on false and try again from the main thread, or the bridge becomes unreachable and its native instance is never freed.

Reimplemented in Csound.Unity.CsoundWorker.

◆ PerformKsmps()

int Csound.Unity.CsoundUnityBridge.PerformKsmps ( )
inline

Advances Csound by one ksmps block, filling the spout buffer, and caches the spout/spin pointers on the first successful call.

Returns

Zero while the performance is ongoing, a positive value when the score has ended, or DestroyedSentinel when this bridge has already been freed. Test for score end with > 0, never != 0 — the latter reads a freed instance as a finished score, which latches performanceFinished and, with domain reload disabled, carries into the next Play session.

> 0 loses nothing: csound.h documents csoundPerformKsmps as returning "false during performance, and true when performance is finished" and defines no negative error return, so there is no error code for this to swallow. CsoundWorker tests the same value with != 0 and is equally correct, because it calls the native function directly and never sees the sentinel.

◆ TryEnterAudio()

bool Csound.Unity.CsoundUnityBridge.TryEnterAudio ( )
inlinepackage

Claims this bridge for the duration of one audio callback. Returns false when the instance is being destroyed, and the caller must then produce silence and return without touching the bridge at all.

Every audio-thread entry point pairs this with ExitAudio in a finally: CsoundUnity.OnAudioFilterRead, CsoundRealtime.Process and CsoundRootRealtime.EndProcessing. It is claimed once per DSP block, not per sample, so the cost is one volatile read and two interlocked operations per block.

The flag is checked twice on purpose. The first check is the cheap common case. The second closes the window where the destroy set _closing between that check and the increment: without it the destroy could see a count of zero, start freeing, and only then have this caller appear.

◆ Paused

volatile bool Csound.Unity.CsoundUnityBridge.Paused

Mirrors the owning CsoundUnity.pauseProcessing flag, for the same reason as Muted. When set, those paths skip PerformKsmps entirely and output silence.

They must nonetheless keep invoking the spin-fill callback that refreshes this flag: it is the only thing that can clear it again, so skipping it would make the pause impossible to lift.

◆ WebGLVariation

int Csound.Unity.CsoundUnityBridge.WebGLVariation = 3
static

Which @csound/browser variation to create: 0 single threaded, 1 worker with a SharedArrayBuffer, 2 worker with a MessagePort. Anything higher clamps to the last. Read only in a WebGL player, and declared outside the guard so that code setting it compiles on every platform.

They differ in how the host reaches Csound, not only in how audio is carried: in the worker variations a channel write is a request posted to the worker, in the single threaded one it is a direct call. Set before the first instance is created.
