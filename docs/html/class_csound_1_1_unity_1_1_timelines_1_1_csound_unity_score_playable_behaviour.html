Detailed Description

PlayableBehaviour for a clip on a CsoundUnityScoreTrack. Sends Csound score events when the clip plays. Supports Score, Swarm, Arpeggio, Euclidean, Stochastic, Chord, Pattern and Step.

Discrete (snapshot-locked) — read ONCE at each cycle boundary and held for the full cycle, so changes take effect at the NEXT cycle start. This mirrors the behaviour of every major DAW (Logic, Cubase…): Arpeggio : scaleIndex · chordIndex · octaves · directionIndex Euclidean: hits · rotation

Continuous — read every frame or per-note; smooth curves make sense. Arpeggio : bpm · pitchBase · noteDuration Euclidean: bpm · pitchBase · noteDuration Swarm : pitchBase · noteDuration · swarmPitchSpread · swarmDelay · swarmDelayVariation

Assign an ITempoProvider via SetTempoProvider to supply the tempo for clips with followSharedTempo enabled.

◆ ApplyStateJson()

bool Csound.Unity.Timelines.CsoundUnityScorePlayableBehaviour.ApplyStateJson ( string json,
bool allowOtherMode = false )
inline

Writes back a state read with ToStateJson. It lands like any other runtime edit: the continuous values at once, while the ones a cycle latches (scale, octaves, euclidean hits and rotation, arpeggio direction, chord type) and the events already scheduled in Csound follow from the next cycle. The step the sequencer is on is left alone, so the restore does not make the sequence jump.

The state is read into a copy first and only written when that copy holds a clip of this same mode, so a state that does not parse, or that says it is another mode, is refused before any field of this clip has been touched. A snapshot can arrive from a file or from the clipboard, where its contents are whatever someone put there.

Parameters
jsonA state from ToStateJson. Empty input does nothing.
allowOtherModeWrite a state saved in another mode, which turns this clip into a clip of that mode. Off by default: a state of another mode reaching a clip by accident would replace everything it plays.
Returns
True when something was written.
