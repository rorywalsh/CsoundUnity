Detailed Description

Splits a run of MIDI bytes into the messages it holds.

A CoreMIDI packet is a run of events sharing one timestamp, not one message, and both the IAC driver and hardware drivers do put several in it. Reading a packet as a single message works for one key at a time and throws the rest away the moment two events arrive together; if the discarded run held a note off, the note never stops.

Deliberately a plain function over a byte[], with no platform guard and no marshalling: the cases that matter here, a packet carrying two messages, running status, a one byte clock, are ones no hardware produces on demand, so they belong in a test. The marshalling stays with the receiver.

int Csound.Unity.MIDI.Internal.MidiPacketSplitter.DataByteCount ( byte status)
inlinestaticpackage

How many data bytes follow a status byte.

Two for the channel messages, except program change and channel pressure, which carry one. Among the system common messages only the time code and song select carry one, and the song position two. The real time messages carry none.

Shared with WindowsMidiReceiver, which gets its message packed in a doubleword rather than in a packet and so needs the same table to know how much of it is a message.
