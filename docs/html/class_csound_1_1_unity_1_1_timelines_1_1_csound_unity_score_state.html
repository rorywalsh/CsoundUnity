Detailed Description

The saved state of every sequencer clip of one timeline. Created from CsoundUnity/Timeline Snapshot in the asset menu, or by the Save button on CsoundUnityTimelineController.

Applied outside play mode it writes into the clips themselves and is permanent; applied in play mode it writes into the behaviours the graph runs, and lasts as long as any other runtime edit.

It saves what a clip plays, and nothing about how the timeline is built: track order, clip positions and durations, blends, animation curves and track bindings are not part of a snapshot and are left exactly as they are.

int stateIndex = 0,
bool verbose = true,

Writes one saved state onto one clip, without matching anything: the caller has the clip in hand and says which state to write. This is what a snapshot of a single clip is for, and it is the reason such a snapshot can be applied to a clip it was never taken from.

The mode has to agree unless allowOtherMode says otherwise, because the fields that carry a pattern mean different things in each, and the state itself is read before anything is written.

Parameters
bThe clip to write to.
stateIndexWhich saved state to write. The only one, for a single clip snapshot.
verboseWhether to log what was written and what was not.
allowOtherModeWrite a state of another mode, which makes the clip a clip of that mode. For an editor that has asked: while the graph runs, the panels have already collected the clips by mode, and one that changes mode under them is shown by the panel of the mode it no longer is.
Returns
Whether the clip was written.

◆ ChangeKey()

string Csound.Unity.Timelines.CsoundUnityScoreState.ChangeKey ( ScoreBehaviour b)
inlinestatic

What a runtime panel can change and a Timeline curve cannot, as one string: the score info, and nothing of the fields Timeline animates. Two equal keys mean nothing has rewritten the score info of this clip.

The whole state is what gets saved; this is only one half of how a change is noticed. Comparing the whole state would call every clip with a curve on any animated field changed at every frame, and the autosave would offer to put back values the curve overwrites immediately. The animated fields are covered the other way round, by ScoreBehaviour.stateSetAtRuntime, which only an explicit write raises.

Parameters
bThe behaviour to read.
Returns
A key that changes whenever anything the state keeps changes.

◆ MatchStates()

int[] Csound.Unity.Timelines.CsoundUnityScoreState.MatchStates ( IList< ScoreBehaviour > behaviours,
bool verbose,
bool byPosition,
out CsoundUnityScoreStateMatch[] hows )
inlinepackage

Which saved state belongs to each behaviour, as an index into clips, or -1 for the ones this snapshot has nothing certain for.

The passes run in order of how much they prove, and each one runs to the end before the next starts: a clip that can be identified claims its state before anything is guessed from a name or a position. An id that belongs to two clips identifies neither, and a name shared by two clips of the set being matched is not used either.

Parameters
behavioursThe behaviours to match, in the order the graph holds them.
verboseWhether each pass logs what it matched and what it left out.
byPositionWhether the behaviours nothing identifies are matched by the order they sit in.
howsHow each behaviour was matched, in the same order.
