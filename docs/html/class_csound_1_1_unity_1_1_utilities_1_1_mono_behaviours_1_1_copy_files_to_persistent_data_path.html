Detailed Description

Copies files from Resources or StreamingAssets into Application.persistentDataPath so that Csound can find them via Environment Variables (e.g. SFDIR, SSDIR, SADIR).

Supported file types:

  • Audio files — any format supported by Csound (wav, aif, …). Place them in a Resources folder as AudioClip assets.
  • Sound fonts — sf2 files. Rename the extension to .bytes or .txt so Unity imports them as TextAsset, then place them in Resources.
  • Csound plugins — desktop only (dylib / dll). Rename to .bytes, place in Resources. On Android / iOS there is no way to load plugins from a runtime path, so they must be bundled at build time instead.
  • Additional binary files — any file importable as TextAsset (.bytes / .txt extension). Useful for wavetables, IRs, or any other data Csound needs to read from disk.
  • StreamingAssets files — files placed in the StreamingAssets folder. On Android these are read via UnityWebRequest; on other platforms they are copied directly.

Setup: keep the CsoundUnity GameObjects inactive when entering Play Mode. This component copies the files first, then activates the listed CsoundUnity instances, ensuring the Environment Variables point to valid files before Csound starts. Set autoStart to false if you need to trigger the copy manually via Copy. It could be extended to support CsoundUnity prefabs too, but for now activation of existing instances is left to the user.

See the Environment/SFDIR and Environment/Load Plugins samples for complete working examples.
